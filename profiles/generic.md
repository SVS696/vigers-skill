# Профиль постановок Generic

## Область

Fallback для проекта без специального профиля. Использует ближайшие проектные
инструкции, актуальные источники и минимальный достаточный шаблон Вигерса.

## Канонические источники

1. Явные решения пользователя.
2. Ближайшие `AGENTS.md`, `CLAUDE.md` и другие объявленные проектом доктрины.
3. Актуальный код, API, схема данных, тикеты и документация.
4. Модель требований и метод Вигерса.
5. Старые постановки только как исторический контекст.

## Системный анализ

- Отделяй факты от решений, предположений и неизвестного.
- Не присваивай пользователю ответственность бизнес-владельца.
- Описывай проверяемое поведение и ограничения, а не реализацию по догадке.

## Архитектурный гейт

Используй общий архитектурный гейт из `SKILL.md`. Дополнительных проектных
триггеров нет.

## Режимы и разбиение

- `compact` — один связный смысловой контур.
- `block` — несколько сценарных/контрактных контуров или большой корпус
  источников; делить по смыслу, не по разделам шаблона.
- В block-mode используй 3–8 блоков: контекст/сценарии, правила/состояния,
  данные/интерфейсы, ошибки/качества, AC/DoD — только применимые сочетания.
- Runtime case храни в отдельной локальной области. Если выбран
  `<project-root>/.vigers/cases/`, каталог `cases/` должен игнорироваться git.

## Артефакт и author gates

Если шаблон проекта не найден, используй минимальную структуру:

- контекст и цель;
- пользователи;
- входит / не входит;
- сценарии и требования;
- данные / интерфейсы / качества — только применимое;
- AC;
- DoD;
- допущения и открытые вопросы.

Контрольные проходы:

1. Простота решения.
2. Логика и трассировка.
3. Чистота прозы для фактической аудитории.
4. Независимый reviewer.
5. Architect conformance по общему гейту.

Project-conformance проверяет только затронутые соглашения из ближайших
инструкций: API/HTTP, identifiers/casing, терминологию, frontmatter, шаблон,
ссылки и имена файлов. При отсутствии правил gate помечается `not_required` с
причиной.

## Жизненный цикл и публикация

Не изменяй внешний трекер и не выбирай канонический путь по догадке. При
отсутствии проектного правила выдай готовый текст в чате или согласованном файле.
