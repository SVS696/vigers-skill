## T05. Пример варианта использования UC-4 — стр. 23

| Поле | Содержание |
|---|---|
| Название | UC-4 «Запросить химикат» |
| Основной актор | Сотрудник, размещающий заказ |
| Дополнительные акторы | Специалист по закупкам; склад; база данных обучения |
| Триггер | Сотрудник хочет заказать химикат |
| Предусловия | Пользователь аутентифицирован; имеет право заказывать; база запасов доступна |
| Постусловия | Запрос сохранен; отправлен на склад или поставщику |
| Приоритет | Высокий |
| Бизнес-правила | BR-28, BR-31 |
| Особое требование | Импорт химической структуры в стандартной кодированной форме |
| Допущение | Импортированная структура корректна |

Основной поток:

1. Сотрудник указывает химикат.
2. Система показывает доступные контейнеры.
3. Сотрудник может открыть историю контейнера.
4. Сотрудник выбирает контейнер либо заказ у поставщика.
5. Сотрудник завершает данные запроса.
6. Система сохраняет запрос и отправляет его на склад.

Альтернатива 4.1: найти химикат в каталогах, выбрать поставщика, размер, класс
и количество контейнеров, затем сохранить и отправить запрос поставщику.
Исключение 4.1.E1: если химиката нет в продаже, предложить другой химикат или
выход.

## T11. Анализ компромиссов качеств — стр. 41

| Обозначение | Смысл |
|---|---|
| `+` | Улучшение качества обычно поддерживает второе качество |
| `−` | Улучшение качества может ухудшить второе качество |
| пусто | Стабильная общая зависимость не заявлена |

Исходная иллюстрация — попарная матрица 16 атрибутов из T08. Для конкретной
системы создай собственную матрицу и обоснуй важные `+` и `−`: зависимости
контекстны, а не являются физическими законами.
